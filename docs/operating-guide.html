Operating guide

How the firm runs its deadlines, clients and enquiries in the system. One obligation table, one reminder engine, one list everyone works from. Written for partners, managers, staff and the administrator who sets it up.

2. Opening the app

Right now the app runs inside this Claude session. Open the preview pane for tab-pms (port 3000), or the address your IT team gives you once it is hosted. The permanent home is decided in the deployment runbook (docs/RUNBOOK.md in the repository); the default target is Azure UAE North so client data stays in the UAE.

First sign-in

  1. Enter your email and password. Demo accounts all use the password TabDemo!2026.
  2. The app shows a QR code. Open Microsoft Authenticator (or Google Authenticator) on your phone, add an account, scan the code, and type the 6-digit number. Two-factor is mandatory for every user and this step happens once.
  3. From then on: email, password, then the current 6-digit code.

Five wrong attempts lock the account for 15 minutes. Sessions last 8 hours. An administrator can reset someone's two-factor from Settings → Users.

4. The working day

Staff: start at My work

My work is one dated list of everything waiting on you: obligations where you are preparer or reviewer (sorted by your deadline, not the statutory one), open tasks, and leads whose next action is due. Red means overdue, amber means due within a week. Work from the top.

At 08:00 Gulf time a digest email lists the same things: overdue, due this week, waiting on your review, leads needing action. If you are marked on leave in Settings → Users, your reminders go to your manager instead.

Managers: Obligations → My team's work

Filter by preparer, status or due date. Use the checkboxes and the Bulk bar to reassign work or send a document request to several clients at once. You receive an escalation email when any obligation in your team passes its internal preparation deadline without being Ready for Submission.

Partners: the Dashboard

Exceptions come first: overdue, due this week with no preparer, unassigned, dates needing review, leads with no next action, clients missing deadline data. Every figure is a live count and clicking it opens the list with exactly that count. Every Monday morning a partner summary email covers your portfolio for the next 14 days. You receive a partner escalation when an obligation is still open three working days before its statutory date.

5. Working a deadline

Every deadline in the firm is an obligation: a VAT return for a tax period, a Corporate Tax return for a financial year, a trade licence renewal, an engagement letter renewal. They are generated automatically every night, 18 months ahead, from the client's year-end, VAT frequency and licence expiry. You do not create routine ones by hand.

Four dates on every obligation

DateMeaningDefault
Statutory due dateWhat the law requires, derived from a named rule version. Never moved.VAT: 28 days after period end · CT: 9 months after period end
Internal targetThe statutory date moved back to the previous working day if it falls on a Saturday, Sunday or UAE public holiday. Shown with * in lists.—
Review deadlineWhen the reviewer should have it.5 working days before the target
Preparation deadlineWhen the preparer should be finished. Missing it triggers the manager escalation.10 working days before the target
The system derives dates from configurable rules; it does not give statutory advice. Each rule says which version produced a date, and a qualified person confirms the rules in Settings → Deadline rules. The firm, not the software, is responsible for the filing date.

The status workflow

Upcoming→Documents Requested→Documents Received→In Preparation→Pending Internal Review→Pending Client Approval→Ready for Submission→Submitted→Payment Pending→Completed
  • Change status straight from the list with the dropdown in the Status column, or open the obligation for a note.
  • Submitted needs the FTA submission reference. The database refuses it without one.
  • Completed needs payment confirmed, or a waiver with a reason (for example a nil return).
  • On Hold needs a reason and stops reminders. Overdue is never set by hand; it is worked out from the dates.
  • Every change records who, when and the note. The history is on the obligation and on the client's Audit Trail tab.

Colour code

Red overdue · Amber due within 7 days · Blue in progress · Green completed · Grey on hold

Four views of the same list

List for daily work and bulk actions · Kanban by status · Calendar by statutory month · Year grid with one row per client and one cell per month, which is the view for spotting a crunch.

When dates are flagged "Review"

If a client's year-end or VAT frequency changes, the system does not rewrite future obligations. It flags them amber with the reason. Open one and choose Keep these dates or Replace with regenerated obligations. Filed obligations are never touched.

6. Clients

Loading the firm's client list

  1. Export the current list to Excel with one row per legal entity. Useful columns: client code, legal name, trade name, entity type, licence number and authority, licence expiry, emirate, financial year-end (as 31/03 or a date), VAT TRN, VAT frequency, first day of any VAT period, CT registration number, primary contact name, email and mobile.
  2. Clients → Import → choose the file. Match each of your columns to a field.
  3. Read the dry run. It lists every row that will be rejected and why: duplicate TRN or licence number (in the file or already in the system), bad dates, missing code or name. Nothing is saved yet.
  4. Fix the spreadsheet or accept the rejections, then Import. Obligations generate immediately for every imported client. 1,500 rows take under a minute.
A client with no financial year-end gets no Corporate Tax deadlines, and one with no VAT period start gets no VAT deadlines. The system never guesses December or a calendar quarter. These clients appear under Missing data in the menu until fixed.

Everyday client work

  • Search finds a client by name, code, VAT TRN, CT number, licence number, or a contact's email or mobile.
  • The profile has nine tabs: Overview, Contacts, Services, Obligations, Documents (Phase 4, not yet built), Communication, Tasks, Notes, Audit Trail.
  • Services are what drives assignment: adding a VAT service with a preparer and manager assigns that client's VAT obligations to them. Add a contract end date and an engagement-renewal obligation is generated.
  • Communication is the unified timeline: logged calls and meetings, status changes, reminders sent, and (once connected) Outlook emails matched by contact address.
  • Bulk reassign on the client list moves a whole portfolio from one manager, preparer or partner to another, including their open obligations, when someone leaves or changes team.
  • Stop work (partners, collections roles) puts a red banner on the client and every one of its obligations.
  • Clients are archived, never deleted. Export view to Excel downloads whatever the current filters show.

7. Enquiries and leads

Every lead must have an owner and a next-action date; the form will not save without them. A lead whose next action has passed appears under Needs attention on the dashboard and its owner gets an email each working day until it is updated.

New→Contacted→Qualified→Proposal Sent→Negotiation→Won/Lost (reason required)
  • Log contact on the lead records the call or email and sets the next action. The first logged contact stops the response-time clock, which the source report shows per source.
  • Convert to client on a won lead creates the client, carries over the contact and notes, creates the services you enter, and generates obligations. You are then taken to the client form to add the year-end, VAT and licence details.
  • The pipeline tiles show count, value and weighted value per stage. The source report shows conversion and average fee per source.

Website form

Your website, Zapier or Power Automate can post enquiries straight in. They arrive assigned to the Business Development person with the fewest open leads, with "First contact" due the next working day. Your web developer needs the address and secret from the administrator:

POST https://<your-app-address>/api/connectors/lead-webhook
Header: x-webhook-secret: <LEAD_WEBHOOK_SECRET>
Body (JSON): name, company, email, phone, service, message

8. Reminders and email

Every hour the worker finds obligations that need a reminder and sends them. Each reminder is recorded once; re-running the job can never send the same email twice. Nothing is sent on a Saturday, Sunday or public holiday; a reminder that would land on one is sent the previous working day. All reminders are listed at the bottom of the obligation they belong to.

WhoWhen (defaults, editable in Settings → Reminder rules)
Preparer30, 15, 7, 3, 1 days before the statutory date, on the day, then every 2 days while overdue
Reviewer7, 3, 1 days before
Manager escalationOnce, when the internal preparation deadline passes without Ready for Submission
Partner escalationOnce, 3 working days before the statutory date if still not Submitted
Client: documents neededVAT 21 and 14 days before; CT 90, 60, 30 days before (while Upcoming or Documents Requested)
Client: approval5, 3, 1 days before, while Pending Client Approval
Client: tax payment3, 1, 0 days before, while Payment Pending
EveryoneDaily digest 08:00 GST; partners also a Monday summary

Two safety switches (Settings → Email)

  • Pause all outbound email: on by default. Reminders are still worked out and logged as "skipped paused" but nothing is sent. They are not re-sent when you un-pause.
  • Test mode: redirects every email to one address with the real recipient in the subject. Use it for the first week.

The banner at the top of every screen shows when email is paused or in test mode, and turns red if a background job failed in the last 24 hours.

9. Microsoft 365 connection

Two different Microsoft connections are involved, and only one is done.

ConnectionWhat it is forStatus
Your account → ClaudeLet Claude read your mailbox and tenant while building. Confirmed: tabconsultantsllc.com, rights include Mail.Send and shared mailboxes.Connected
The application → Microsoft GraphLets the system send reminders from a shared mailbox and attach Outlook emails to client timelines, unattended, 24 hours a day. Needs its own app registration, which only a Microsoft 365 global administrator can create.Not yet
The application → Microsoft Entra sign-in"Sign in with Microsoft" for staff, relying on Entra's own MFA.Not yet

A people search of your tenant did not surface a compliance@ shared mailbox, so one probably needs creating. The full admin steps are in docs/CONNECTORS.md in the repository; in short:

  1. In the Microsoft 365 admin centre, create a shared mailbox, for example compliance@tabconsultantsllc.com.
  2. In Entra, register an application TAB PMS – Mail with application permissions Mail.Send and Mail.Read, grant admin consent, create a client secret.
  3. Restrict that application to the compliance mailbox with an Exchange application access policy, so it cannot touch any other mailbox.
  4. Give the tenant ID, client ID and secret to whoever hosts the app; they go into the server's environment variables, never into the app itself.
  5. In the app: Settings → Email → sender mailbox, keep email paused, set test mode to your own address, run Settings → Jobs → send-reminders, and check what arrives. Then clear test mode and un-pause.
  6. Optionally register a second application for sign-in, add the callback address, and require MFA for it with Conditional Access.
Until this is done the system still works fully: deadlines generate, statuses and history are kept, the dashboard and work queues are live. Only email leaves the building later.

11. Go-live checklist

  • Hosting region and provider chosen; app, worker and database deployed (docs/RUNBOOK.md).
  • Production seeded with SEED_DEMO=false; demo accounts not present.
  • Deadline rules confirmed by a qualified person; holidays reviewed.
  • All staff added with roles, managers and two-factor enrolled.
  • Client list imported; Missing data report empty or understood.
  • Services added per client so every obligation has a preparer (dashboard "Unassigned" at zero).
  • Microsoft Graph app registered; test-mode email run checked by a partner.
  • Client-facing reminder wording approved; email un-paused.
  • Website form pointed at the lead webhook.
  • Uptime monitor on /api/health; daily backups on, restore tested once.
  • Used daily for a week before Phase 3 (invoicing and collections) is commissioned.
